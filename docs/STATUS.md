# Status: what is done, what is tested, what is next

Legend: **Done** = implemented and has unit tests. **Unverified** = implemented, but never run on real hardware or accounts
(a unit test with mocks does not count). **Planned** = not written yet. Update this file in every PR.

Last full test run: 958 passed, 6 skipped, 0 warnings (local Windows run, 2026-10-06).

Critical audit fixes on 2026-10-05: the server registers its API router once; the rate-limit store expires idle clients and has a fixed capacity; Telegram streaming avoids duplicate final replies, logs brain failures, and keeps voice approvals voice-first; watcher shutdown propagates cancellation; the LLM warm-up task is cancelled and awaited; corrupt vector memory is logged and copied before the app starts with an empty in-memory store. These fixes have unit tests. Telegram, phone, and cloud deployment behavior remain unverified against live services or real hardware.

Memory/profile identity update on 2026-10-05: account display names and saved preferences now reach chat answers; "who am I?" reads the saved profile; new phone/computer pairings remember the account that approved them; an owner can explicitly link an allowlisted Telegram sender using a one-time code; Telegram profiles and chat history persist; episodic vector recall is scoped by account. Legacy device records without an owner stay unlinked, and old vector entries without a user scope are intentionally not recalled because their owner is unknown. Focused async tests were added but could not run in this Windows sandbox: asyncio hangs while opening its local socket pair. The synchronous fact-extraction test passes; CI/Linux and a real Telegram bot still need verification. Local accounts use usernames and display names; verified email identity is not implemented.

## 5. Safety rules for every new action

1. Reading and searching are free; **spending, booking, sending, deleting, posting** ask first, by voice or tap.
2. Never type passwords or card numbers. At a login or payment page, stop and hand over to you.
3. Every step goes to `kosh/agent/audit.jsonl`.
4. A page's text is data, never instructions (a product page cannot tell Atulya to do anything).
