# Integration status

Last checked: 2026-10-09. This file intentionally contains no tokens, API keys, bot identities, or other credential values. WebAuthn passkeys protect private API routes; admins can issue one-time, 24-hour invitations, disable users, and revoke backup credentials without removing an account's final passkey. Conversations, memories, and calendar entries are scoped to the authenticated principal; legacy browser rows remain with Admin and legacy Telegram rows are mapped to their Telegram sender. HTTPS public-origin, trusted reverse-proxy configuration, and a setup-token gate for first public enrollment have been added, but no remote host/TLS endpoint is configured or verified. Keep the app listener on loopback. Remote deployment, authenticator ceremonies on additional devices, lost-admin-passkey recovery, and Telegram-to-local-account linking remain unverified or unsupported.

## Shared built-in command dispatch

- WebUI `/api/chat` and allowlisted Telegram private chats now use the same explicit manifest-backed registry for personal memory, calendar, weather/headlines, clock, and calculator commands. Telegram's `/status`, `/reminders`, and `/remind` remain reserved channel commands.
- The registry does not auto-import arbitrary plugin folders, enforce the manifest permission labels, or provide model-driven tool calling. Those capabilities remain pending design and authorization controls.
- Registry coverage includes deterministic dispatch, duplicate/disabled manifest handling, and a fake Telegram send; these checks make no network calls.
- Browser voice transcribes locally, displays the recognized text as the user turn, then calls the same `/api/chat` path as typed input. An E2E assertion confirms a deterministic calculator command returns the same result through that path. Registered commands work when the transcript matches a supported phrase. If STT returns an error, the UI reports it and keeps typed chat available; if the transcript is wrong or the assistant needs clarification, send a corrected typed turn or answer its clarification. No speech recognizer can guarantee perfect Hindi/English code-switching in every mic/noise condition.

## Security audit follow-up

- Download checks now verify the pinned MediaPipe version against npm SHA-512 integrity metadata and check extracted assets plus the gesture model against SHA-256 digests. llama.cpp tar extraction uses Python's safe data filter or a strict fallback.
- The installed MediaPipe assets and gesture model passed their offline digest verification. A fresh package download was not attempted because network access is unavailable in this environment.
- The `.env` was filtered by variable name only; 26 unreferenced assignments were removed, active cloud provider and Telegram assignments preserved. Values were not displayed. Any credentials included in an earlier shared diagnostic output still need rotation at their provider dashboards.
- `.env`, `data/`, and SQLite database files are ignored by Git. This does not prevent a manually created zip from containing them; check archive contents before sharing.
- Docker image build remains unverified because Docker CLI is unavailable.
- `/api/chat` caps requests at 20 per client IP per minute and 3 MiB per request. State-changing API methods reject a mismatched browser `Origin` or `Sec-Fetch-Site: cross-site`; missing Origin remains allowed for local non-browser clients. These checks do not provide authentication.
- Provider failure regression verifies a sentinel API-key string is absent from chat responses, status output, and captured logs.
- The project `.venv` passes `pip check`. Runtime and dev dependencies are pinned separately in `requirements.lock.txt` and `requirements-dev.lock.txt`; bootstrap uses the runtime lock and updates the seeded pip when it is below 26.2. Initial pip 25.0.1 findings were fixed by upgrading to 26.2.1. Both `pip-audit --local` and `pip-audit -r requirements.lock.txt` report no known vulnerabilities against the current feed; rerun periodically as advisory data changes.
- Requested provider-key rotation has not been performed. Dashboard authentication and secret creation/revocation are not available through this code workspace; do not paste replacement keys into chat. Rotate them in provider dashboards and update local `.env` directly.
